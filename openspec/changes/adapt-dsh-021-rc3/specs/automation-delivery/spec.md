# Spec Delta

## MODIFIED Requirements

### Requirement: F011 官方基线

系统 SHALL 满足本条既有行为与验收约束。来源：冻结的 [SPEC F011](../../../../../docs/SPEC.md)；确认、历史实现与验证依据见 [迁移索引](../../../../MIGRATION.md)。

- 预期：本条的精确组合预检与不匹配拒绝原则保留；旧 F011 的 Desktop/Bundle/三个成员0.2.0-rc.2是历史组合。后续已确认 [2026-10-17升级契约](../../../../../docs/DSH-UPGRADE-20261017.md)将目标改为Desktop0.2.1-rc.3，官方会话自动任务内建web-app，相应入口与所有者依新公开接口。
- 当前完整包修订以F018为准；不能把旧F011历史数值重新写入安装配置。

#### Scenario: 核对当前组合

- **WHEN** 加载目标Desktop0.2.1-rc.3组合
- **THEN** 采用后续确认的当前宿主与公开接口，官方自动任务由web-app内建；缺必需能力拒绝增强并保留诊断，不重新要求旧独立schedule包。



### Requirement: F018 统一版本与固定交付

系统 SHALL 满足本条既有行为与验收约束。来源：冻结的 [SPEC F018](../../../../../docs/SPEC.md)；确认、历史实现与验证依据见 [迁移索引](../../../../MIGRATION.md)。

插件 SHALL 使用完整宿主基线加整数修订号交付，并核对源码与产物身份，保持独立安装、旧配置及业务资料；下列场景保留原迁移与交付断言。

#### Scenario: 完整修订与旧后缀

- **WHEN** 从旧automation专用后缀迁往0.2.1-rc.3+rev.1
- **THEN** 使用完整版本、源码SHA、产物散列及明确旧锁映射，+rev.N按安全正整数比较且跨基线拒绝。
- **AND** 包版本统一为 0.2.1-rc.3+rev.1；宿主与官方 peers 仍为实际要求的原版本。完整字符串、源码 SHA 和产物散列同时校验，不能使用忽略 build metadata 的 SemVer 判断修订升级。
- **AND** Chatty／Automation 的原比较接口保留，规范后缀改为 +rev.N，N 为无前导零的安全正整数；跨官方基线拒绝。旧版本仅由明确迁移映射及原锁／散列接管，不能把旧后缀 .1 与 rev.1 当作无需更新。
- **AND** 本包继续独立安装，不进入办公套件；启停和业务配置语义保持。
- **AND** 配置／数据：没有业务字段改名或存储搬迁；套件接管仅处理组合选择与既有 disabled 字段，保留未知配置、工具引用、文档和凭据。迁移 CAS／备份／冲突／回滚由根维护入口执行。
- **AND** 验收：完整产物、版本迁移、原功能回归；成员还需唯一实例、旧配置命中、总／子开关与业务资料保留。具体记录见 VERIFICATION-OFFICE-20261018.md（完成后生成）。

#### Scenario: 独立插件交付

- **WHEN** 根固定组合交付自动化增强
- **THEN** 保持独立安装；未知配置、既有任务、工具引用与凭据保留，数据不因统一名称和版本而搬迁。
