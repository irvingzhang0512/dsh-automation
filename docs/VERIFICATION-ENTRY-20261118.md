# 自动化任务入口恢复

## 修复依据与原因

2026-11-18 用户反馈任务页面缺少两类任务切换，并要求按已有预期直接修复。依据为现行 automation-tools-ui F016。同页包装注册已生效，但漏传官方任务页声明的 store，官方组件读取 useStore 时失败，宿主回退到官方原页面。

0.2.2-rc.3+rev.2 转发同一官方条目的 store，与既有 inject、locale 共同提供完整组件属性。任务来源和调度继续遵循现行契约。

## 验证

- 使用 DSH Desktop 0.2.2-rc.3 原生隔离实例复现修复前的入口缺失，确认增强已注册但未呈现。
- 修复后原生页面显示会话任务、直接任务和新建直接任务。官方清单为空时，合成直接任务可显示并访问既有操作。
- 匹配目标宿主的开发 SDK 下，类型检查、157 项测试及构建通过。既有注册生命周期和产物测试增加 store 身份断言。
- 日常安装和实际任务只读检查待完成。配置页会话概览属于另一份待确认变更，进度由该变更独立记录。

证据位于本机隔离目录 .local/automation-entry-fix-20261118。原生截图为固定视口验证，外部模型服务及用户试用单列。
